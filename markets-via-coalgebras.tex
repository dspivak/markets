\begin{abstract}
\noindent We model economic agents by asking less of them than
classical theory does: an agent need not carry a utility function or
a theory of prices, only a menu of trades it currently accepts and a
deterministic state update for each executed trade and observation.
Exchange events among such agents---trades that conserve value,
draw from exposed menus, and update states consistently---generate a
prop whose morphisms are all possible trading histories.  Markets
then appear as agents one level up: a market-agent's hidden state
selects, from each context of exposed menus, the deal that actually
executes, packaging matching engines and social ambience alike as
state-dependent response rules.  Throughout
we use the language of polynomial functors, and we record a
conjectural factorization separating an agent's behavior from its
portfolio.
\end{abstract}

In what follows, we fix a resource set $R$ carrying the structure of a commutative monoid $(R,+,0)$, so that holdings $x, y \in R$ combine additively, $x+y \in R$.  The default mental picture is the free commutative monoid on a set of named fungible resources $\{ r_1, r_2, \ldots, r_n \}$: each holding is a finite formal sum $\sum_i n_i r_i$ of non-negative whole-number multiplicities $n_i$ of the resource $r_i$.  Assuming $R$ to be a group instead introduces negative elements, which forces the model to consider idealized debt for all assets in every trade scenario. Assuming RR
R supports rational coefficients likewise forces fractional holdings everywhere.%
\footnote{Even the assumption that holdings can be added seems brutal---not all economic resources worth considering are fungible! To describe the theory that allows for non-fungible resources, take $R$ to be a set, holdings to be subsets, and all arithmetic related to holdings would need to be replaced by corresponding abstractions applied to subsets. Instead of ``Alice gains 2 apples" being modeled by ``$r \mapsto r + 2r_{\textrm{apple}}$" it might look like ``$r \mapsto r \cup \{ \textrm{apple}_{203}, \textrm{apple}_{45305} \}$." While that paper would be fun to write, we woke up that day and chose kindness.}

\section*{Agents}

\subsection*{What are we trying to model?}

\noindent An economic agent has: 
\begin{enumerate}
	\item a portfolio
	\item \label{itm:state} beliefs, risk limits, things like inventory contraints
	\item some way to make trading decisions that depends on \ref{itm:state}
	\item some way to update its beliefs/risk limits/inventory constraints after making a trade
	\item some way to incorporate observations about the world when making those updates.
\end{enumerate}

So an agent has a portfolio; it has some set of internal states; it has a trading policy that depends on its state. Rather than assuming that every agent has a coherent theory of market prices encoded in a utility function, we ask less of an economic agent: the agent only needs to know which trades it is willing to accept. Whenever an acceptable trade is executed, the agent's state updates deterministically according to the information made available by the event.

\begin{definition} \label{def-of-agent}
Fix a set $X$ of local observations.  An \emph{agent} of type $X$ consists of:
\begin{enumerate}[nosep]
\item a current portfolio $r\in R$;
\item a set $A$ of \emph{states};
\item a current state $a\in A$;
\item for each state $b \in A$, a \emph{trade menu} $T_b \subseteq R \times R$, whose elements $(g,h)$ mean ``give $g$, receive $h$'';
\item for each state $b \in A$, an \emph{update map} $f_b \colon T_b \times X \to A$.
\end{enumerate}
\end{definition}

\begin{example}[Running example] \label{ex:running}
In this example, $X = 1$, so the update map at a state $b$ collapses to $f_b \colon T_b \to A$; for a trade $t=(g,h)$, we write the update as $f_b(t)$.
Let $R = \mathbb{R}^2$ with coordinates $(c, q)$, where $c$ is cash and $q$ is the quantity of one asset.  Consider two agents, Alice and Bob, initially in states \texttt{eager} and \texttt{hold}, with portfolios $v_A = (1000, 0)$ and $v_B = (200, 20)$.

\medskip
\noindent\textbf{Alice} has state space $A = \{\texttt{eager},\,\texttt{cautious}\}$:
\begin{center}
\renewcommand{\arraystretch}{1.3}
\begin{tabular}{p{2.2cm}p{5.8cm}p{5cm}}
\hline
State $b$ & Trade menu $T_b$ & Transition $f_b(t)$ \\
\hline
$\texttt{eager}$ & buy up to 5 shares at $\leq\$102$ each & $\texttt{cautious}$ for all $t \in T_{\texttt{eager}}$ \\
$\texttt{cautious}$ & buy up to 2 shares at $\leq\$98$ each & $\texttt{cautious}$ for all $t \in T_{\texttt{cautious}}$ \\
\hline
\end{tabular}
\end{center}

\medskip
\noindent\textbf{Bob} has state space $B = \{\texttt{hold}\}$:
\begin{center}
\renewcommand{\arraystretch}{1.3}
\begin{tabular}{p{2.2cm}p{5.8cm}p{5cm}}
\hline
State $b$ & Trade menu $T_b$ & Transition $f_b(t)$ \\
\hline
$\texttt{hold}$ & sell up to 10 shares at $\geq\$100$ each & $\texttt{hold}$ for all $t \in T_{\texttt{hold}}$ \\
\hline
\end{tabular}
\end{center}
\end{example}

\begin{example}[Nontrivial observations]\label{ex:nontrivial-observations}
The running example takes $X=1$ only to keep the notation light.  One could instead take
\[
X=C\times S,
\]
where $C$ records information about the counterparty and $S$ records an outside price signal, such as the current price of a related asset.  Then Alice's update has the form
\[
f_b(t,c,p),
\]
so the same executed trade $t$ may lead to different next states depending on who filled it and what other market information arrived with the fill.
\end{example}

\subsection*{What counts as economic activity?}
An event involves some number of agents simultaneously.  Each agent enters with a current state and a current portfolio and exits with a (possibly different) state and portfolio.  The underlying behavioral data from Definition \ref{def-of-agent}---state set, trade menus, and update maps---does not change for any agent during an event.  What can change is the distribution of resources and the state of each agent.

Let $\Set{Agent}$ denote the class of all tuples $(A, \tau, a, v)$ where $\tau$ represents the portfolio-free behavioral data $(T_-,f_-)$ on $A$, $a\in A$ is the current state, and $v \in R$ is the current portfolio.  We draw an event as a box, as will later be used in string diagrams.  Each wire carries an agent.  Wires entering from the left are the agents before the event; wires exiting to the right are the agents after.

\[
\begin{tikzpicture}[oriented WD, bby=2.5ex, bbx=1.5cm, bb port sep=1.5, bb min width=1.2cm]
  \node[bb={2}{2}] (E) {event};
  \draw (E_in1) to +(-.4cm,0) node[left, font=\scriptsize] {$(A_1,\tau_1,a_1,v_1)$};
  \draw (E_in2) to +(-.4cm,0) node[left, font=\scriptsize] {$(A_n,\tau_n,a_n,v_n)$};
  \draw (E_out1) to +(.4cm,0) node[right, font=\scriptsize] {$(A_1,\tau_1,a'_1,v'_1)$};
  \draw (E_out2) to +(.4cm,0) node[right, font=\scriptsize] {$(A_n,\tau_n,a'_n,v'_n)$};
  \node[above left=-9pt and 0] at ($(E_in1)!.5!(E_in2)$) {$\vdots$};
  \node[above right=-9pt and 0] at ($(E_out1)!.5!(E_out2)$) {$\vdots$};
\end{tikzpicture}
\]
There will be three conditions for such a box to be a valid economic event: that there is no change between total assets entering and exiting the event, that each selected trade lies in the agent's current menu and realizes the agent's portfolio change, and that each agent's current state when exiting the event is determined by their update map and local observation applied to the trade they participated in.
\begin{definition}
Let $x,x'\colon I\to\Set{Agent}$ with $x(i)=(A_i,\tau_i,a_i,v_i)$ and $x'(i)=(A_i,\tau_i,a_i',v_i')$ for each $i\in I$, and write $(T_i,f_i)\coloneqq\tau_i(a_i)$.  An \emph{exchange event}, written
\[e\colon x\to x',\]
consists of trade-observation pairs $(t_i,x_i)\in T_i\times X$ for each $i\in I$ such that three conditions hold:
\begin{description}
	\item[\quad Value conservation:%
\footnote{Some markets charge a fee, or even destroy assets, which seems to violate conservation; but these can be modeled by including extra agents that ``belong to the market'' or that take ownership of destroyed assets, as happens explicitly on the Ethereum network.  This conservation law is local, and does not imply global conservation of value.}
]%
	$\sum_{i\in I} v_i=\sum_{i\in I}v_i'$
	\item[\quad Trade consistency:] writing $t_i=(g_i,h_i)$, there is some $k_i\in R$ such that $v_i=k_i+g_i$ and $v_i'=k_i+h_i$, for each $i$, and
	\item[\quad Update consistency:] $f_i(t_i,x_i)=a_i'$, for each $i$.
\end{description}
\end{definition}


\begin{example}\label{ex:event}
Alice is in state \texttt{eager} with portfolio $v_A = (1000, 0)$; Bob is in state \texttt{hold} with $v_B = (200, 20)$.  As in the running example, $X=1$, so the observation components are omitted.  An event in which Alice buys 3 shares from Bob at \$100 each:

\begin{center}
\begin{tikzpicture}[oriented WD, bby=2.5ex, bbx=1.5cm, bb port sep=1, bb min width=1.2cm]
  \node[bb={2}{2}] (E) {$e_1$};
  \draw[blue!70!black] (E_in1) to +(-.4cm,0) node[left, font=\scriptsize, text=blue!70!black] {Alice: $(\texttt{eager},\;(1000,0))$};
  \draw[red!60!black] (E_in2) to +(-.4cm,0) node[left, font=\scriptsize, text=red!60!black] {Bob: $(\texttt{hold},\;(200,20))$};
  \draw[blue!70!black] (E_out1) to +(.4cm,0) node[right, font=\scriptsize, text=blue!70!black] {$(\texttt{cautious},\;(700,3))$};
  \draw[red!60!black] (E_out2) to +(.4cm,0) node[right, font=\scriptsize, text=red!60!black] {$(\texttt{hold},\;(500,17))$};
\end{tikzpicture}

\noindent\emph{Value conservation:} $(1000,0) + (200,20) = (1200, 20) = (700,3) + (500,17) $.

\noindent\emph{Trade consistency:}
\begin{itemize}[nosep]
\item Alice in state \texttt{eager} accepts buying up to 5 shares at $\leq\$102$.  The trade is 3 shares at \$100, so $t_A\coloneqq((300,0),(0,3)) \in T_{\texttt{eager}}$: Alice gives \$300 and receives 3 shares.
\item Bob in \texttt{hold} accepts selling up to 10 at $\geq\$100$.  The corresponding sell-side trade is $t_B\coloneqq((0,3),(300,0)) \in T_{\texttt{hold}}$: Bob gives 3 shares and receives \$300.
\end{itemize}

\noindent\emph{Update consistency:}
\begin{itemize}[nosep]
\item $f_{\texttt{eager}}(t_A) = \texttt{cautious} = a'_A$.
\item $f_{\texttt{hold}}(t_B) = \texttt{hold} = a'_B$.
\qedhere
\end{itemize}
\end{example}

\section*{The event prop}
%% ===================================================================

Exchange events capture one-step resource transfers between current agents.  We now pass from individual events to the compositional structure of trading histories themselves.  The basic units are one-step exchange events, and the event prop records how such events compose in parallel and in time.

Our next goal is to define a colored prop with $\Set{Agent}$ as the set of colors.  Given $x\colon I\to\Set{Agent}$ and $y\colon J\to\Set{Agent}$, we write $(x,y)\colon I+J\to\Set{Agent}$ for their copairing.

\begin{proposition}\label{prop:parallel}
Given events $e\colon x\to x'$ and $f\colon y\to y'$, where $x,x'\colon I\to\Set{Agent}$ and $y,y'\colon J\to\Set{Agent}$, there exists an event
\[(e,f)\colon (x,y)\to (x',y').\]
\[
\begin{tikzpicture}[oriented WD, bby=2.5ex, bbx=1.5cm, bb port sep=1, bb min width=1cm]
  \node[bb={1}{1}] (E) {$e$};
  \node[bb={1}{1}, below=1 of E] (F) {$f$};
  \draw (E_in1) to +(-.5cm,0) node[left, font=\scriptsize] {$x$};
  \draw (F_in1) to +(-.5cm,0) node[left, font=\scriptsize] {$y$};
  \draw (E_out1) to +(.5cm,0) node[right, font=\scriptsize] {$x'$};
  \draw (F_out1) to +(.5cm,0) node[right, font=\scriptsize] {$y'$};
\end{tikzpicture}
\]
\end{proposition}

\begin{proof}
We just need to check the requirements. Value conservation holds $\sum_{i\in I}v_i+\sum_{j\in J}v_j=\sum_{i\in I}v'_i+\sum_{j\in J}v'_j$, since each sum holds separately.  Trade consistency and update consistency hold for each participant, since they hold in $e$ and $f$ respectively.
\end{proof}


\Cref{prop:parallel} shows that exchange events are closed under parallel composition.  They are \emph{not} closed under sequential composition in general.

For a concrete example, suppose Alice has three states $a_0,a_1,a_2$.  In state $a_0$ she will buy one share for \$100 and then move to $a_1$; in state $a_1$ she will buy one share for \$101 and then move to $a_2$.  Bob's state is fixed, and his menu contains the corresponding sell trades.  Starting from Alice's portfolio $(1000,0)$ and Bob's portfolio $(0,2)$, let $e_1$ and $e_2$ be the following two trades:
\[
\begin{tikzpicture}[oriented WD, bby=2.5ex, bbx=1.5cm, bb port sep=1, bb min width=1cm]
  \node[bb={2}{2}] (E1) {$e_1$};
  \node[bb={2}{2}, right=2 of E1] (E2) {$e_2$};
  \draw[blue!70!black] (E1_in1) to +(-.4cm,0) node[left, font=\scriptsize, text=blue!70!black] {Alice: $(a_0,(1000,0))$};
  \draw[red!60!black] (E1_in2) to +(-.4cm,0) node[left, font=\scriptsize, text=red!60!black] {Bob: $(b,(0,2))$};
  \draw[blue!70!black] (E1_out1) to node[above, font=\scriptsize, text=blue!70!black] {$(a_1,(900,1))$} (E2_in1);
  \draw[red!60!black] (E1_out2) to node[below, font=\scriptsize, text=red!60!black] {$(b,(100,1))$} (E2_in2);
  \draw[blue!70!black] (E2_out1) to +(.4cm,0) node[right, font=\scriptsize, text=blue!70!black] {$(a_2,(799,2))$};
  \draw[red!60!black] (E2_out2) to +(.4cm,0) node[right, font=\scriptsize, text=red!60!black] {$(b,(201,0))$};
\end{tikzpicture}
\]
In $e_1$, Alice's trade is $((100,0),(0,1))$ and Bob's is $((0,1),(100,0))$.  In $e_2$, Alice's trade is $((101,0),(0,1))$ and Bob's is $((0,1),(101,0))$.  Each step is an exchange event.  But there is no single exchange event from the initial pair to the final pair: Alice's menu in state $a_0$ contains only the first buy trade, not the net trade $((201,0),(0,2))$, and her update map from $a_0$ moves to $a_1$, not directly to $a_2$.  Thus trade consistency and update consistency both depend on the intermediate state.

We therefore seek a categorical structure that accommodates both parallel and sequential composition of events, without requiring sequential composites to be one-step events.

\begin{definition}[Prop graph]\label{def:prop-graph}
A \emph{prop graph} consists of a set $C$ of \emph{colors}, a set $E$ of \emph{edges} equipped with a monoid structure $(E,e_0,*)$, and monoid homomorphisms $\src,\tgt\colon E\to C^*$, where $C^*$ denotes the free monoid on~$C$.
\end{definition}
In other words, the source of each edge is a list of colors, and the source of the product of two edges is the list concatenation of the two source lists (and respectively for targets).

\begin{example}\label{ex:prop-graph}
Exchange events form a prop graph $G$ with color set $\Set{Agent}$, edge set the class of exchange events, source and target maps reading off the input and output agent families, and edge monoid given by \cref{prop:parallel}.
\end{example}

\begin{definition}[Prop]\label{def:prop}
Let $C$ be a set.  A \emph{$C$-colored prop} is a strict monoidal category whose monoid of objects is the free monoid~$C^*$.
\end{definition}

As one might expect, there is an adjunction between prop graphs and props.

\begin{theorem}[Free prop on a prop graph]\label{thm:free-prop}
For any set $C$ the functor $U\colon\prop_C\to\propgr_C$ has a left adjoint
\[
\adj{\propgr_C}{\Free}{U}{\prop_C}
\]
and we call $\Free(G)\in\prop$ the \emph{free prop} on a prop graph $G$.
\end{theorem}
\begin{proof}
The operad whose algebras are $C$-colored prop graphs embeds into the operad whose algebras are $C$-colored props \cite{PattersonSpivakVagner}, and any map of operads induces an adjunction between the corresponding algebra categories.
\end{proof}

Given a prop graph $G$, the free prop $\Free(G)$ has the same objects. The morphisms in $\Free(G)$ are given by monoidal string diagrams with boxes labeled in the edges of $G$, modulo an equivalence relation: any occurrence of parallel boxes labeled $e$ and $e'$ can be replaced by a single box labeled $e*e'$ and the resulting morphisms are made equal.

\begin{definition}[Event prop]\label{def:event-prop}
Define the \emph{event prop} $\Event$ to be the free prop $\Free(G)$ on the prop graph of exchange events from \cref{ex:prop-graph}.  Its morphisms are multi-step trading histories: equivalence classes of string diagrams whose boxes are one-step exchange events.
\end{definition}

\begin{proposition}
Every morphism $e\colon (I,x)\to (J,y)$ in the event prop has the same number of inputs as outputs, $I=J$, and satisfies value conservation. 

Moreover, for each $i:I$ with $x_i=(A_i,\tau_i,a_i,v_i)$ and $y_i=(A_i, \tau_i, a_i', v_i')$, there exists a nonempty sequence of states and values $(a^1,v^1),\ldots,(a^{N+1},v^{N+1})$ such that $(a_i,v_i)=(a^1,v^1)$, $(a_i', v_i')=(a^{N+1},v^{N+1})$, and for each $1\leq n\leq N$:
\[
\begin{aligned}
	\tau_i(a^n)&=(T^n,f^n),\where (t^n,x^n)\in T^nX,\\
	t^n&=(v^n,v^{n+1}),\qand f^n(t^n,x^n)=a^{n+1}.
\end{aligned}
\]
\end{proposition}

**
\end{proof}

The event prop $\Event$ contains all possible trading histories consistent with value conservation, trade consistency, and update consistency: every way that agents could exchange resources, in any order, with any wiring.

A \emph{market} should be some structured collection of events in $\Event$---the events that a particular market mechanism permits.  The eventual goal of this work is to pick out collections corresponding to specific real-world markets, and to ask whether this framework can recover existing financial mathematics or reveal structure that was not visible before.

We begin by formalizing the intuition that different markets ``act" in different ways.

%% ===================================================================
\section*{Markets as Agents}
%% ===================================================================

\textbf{Informal picture.}
Participants often reason about a market as though it has internal state and repeatable behavior.  Given exposed trade menus, the market selects trades, supplies observations, and changes what it will do next.  This may describe an actual mechanism, such as an algorithmic exchange, or it may be a useful fiction induced by participants' modeling of the aggregate system.

The purpose of this section is to make that market-agent visible before introducing the formal notation.  An ordinary agent has a state, a trade menu in each state, and an update rule.  A market-agent has the same shape of description at the next scale: it has a market state, a rule for responding to the finite list of menus currently exposed by the participants, and an update rule for its own state.

\begin{center}
\begin{tikzpicture}[oriented WD, bby=2.5ex, bbx=1.5cm, bb port sep=1.3, bb min width=2.2cm]
  \node[bb={3}{3}] (M) {market-agent};
  \draw (M_in1) to +(-.8cm,0) node[left, font=\scriptsize] {$T_{a_1}$};
  \draw (M_in2) to +(-.8cm,0) node[left, font=\scriptsize] {$T_{a_2}$};
  \draw (M_in3) to +(-.8cm,0) node[left, font=\scriptsize] {$T_{a_n}$};
  \draw (M_out1) to +(.8cm,0) node[right, font=\scriptsize] {$(t_1,x_1)$};
  \draw (M_out2) to +(.8cm,0) node[right, font=\scriptsize] {$(t_2,x_2)$};
  \draw (M_out3) to +(.8cm,0) node[right, font=\scriptsize] {$(t_n,x_n)$};
  \node[font=\scriptsize] at ($(M_in2)!.5!(M_in3)+(-.8cm,0)$) {$\vdots$};
  \node[font=\scriptsize] at ($(M_out2)!.5!(M_out3)+(.8cm,0)$) {$\vdots$};
  \node[above=1.2ex of M, font=\scriptsize] {market state $m$};
  \node[below=1.2ex of M, font=\scriptsize] {updates to $m'$};
\end{tikzpicture}
\end{center}

\textbf{Separating behavior from holdings.}
For this step we temporarily separate an agent's behavioral state from its current portfolio.  In state $b\in A$, an agent exposes a menu $T_b\subseteq R\times R$ of acceptable visible swaps and has an update map
\[
T_b\times X\to A.
\]
A direction $(t,x)$ records the trade $t=(g,h)$ that was executed---give $g$, receive $h$---together with the local observation $x$ supplied to the agent.  The current portfolio is not discarded; it is carried alongside the state and is changed by events.  The point of the temporary separation is that the behavioral part can be packaged first, and portfolios can then be reintroduced as an additional component.

\begin{example}\label{ex:agent-without-portfolio}
Take $X = 1$, so each direction is a trade alone.  Alice from Example~\ref{ex:event} has state set $A_{\mathrm{Alice}} = \{\texttt{eager}, \texttt{cautious}\}$, menus $T_{\texttt{eager}}$ (buy up to 5 shares at $\leq \$102$) and $T_{\texttt{cautious}}$ (buy up to 2 shares at $\leq \$98$), and update maps $T_b \to A_{\mathrm{Alice}}$ sending every direction to $\texttt{cautious}$.  Bob has state set $\{\texttt{hold}\}$, single menu $T_{\texttt{hold}}$ (sell up to 10 shares at $\geq \$100$), and update returning to $\texttt{hold}$.  The portfolios $(1000,0)$ and $(200,20)$ live outside the state sets; events act on them.
\end{example}

\textbf{Exposed menus and market response.}
A market mediates many exposed menus at once.  If $n$ participants expose menus $(T_1,\ldots,T_n)$, then a market response chooses one trade-and-observation pair from each menu:
\[
((t_1,x_1),\ldots,(t_n,x_n))\in T_1X\cdots T_nX.
\]
Here $T_iX$ denotes $T_i\times X$.  Such a response is exactly the extra mechanism-side data missing from a bare exchange event: the event records what happened to the agents, while the market response records how the selected trades were produced from the exposed menus.

A market-agent is the stateful object that answers every finite menu context.  In market state $m$, it has a response rule
\[
\epsilon_m(T_1,\ldots,T_n)=((t_1,x_1),\ldots,(t_n,x_n))
\]
and an update rule
\[
u_m(T_1,\ldots,T_n)=m'
\]
sending the presented menu context to the next market state.  Different state spaces, response rules, and update rules model different mechanisms.  For a centralized exchange such as an NYSE-style central limit order book, the market agent may be close to literal: the market state can include book state and the response rule can encode matching behavior.  For a decentralized system such as Bitcoin, there need not be one literal market agent; different choices of state space can model miners, mempool state, block selection, or the aggregate mechanism that participants use as a predictive fiction --- i.e.\ the global state of the blockchain, or the global ledger.

\begin{example}\label{ex:market-agent}
Three market-agents, given the same exposed menus from Alice and Bob, can produce events with different relationships.  $M_1$ and $M_2$ produce two different events.  $M_1$ and $M_1'$ are different market-agents producing the same event, illustrating that a single one-step observation does not determine the market-agent.

Reuse Alice (state \texttt{eager}, portfolio $v_A = (1000, 0)$) and Bob (state \texttt{hold}, portfolio $v_B = (200, 20)$) from Example~\ref{ex:event}.  Take $X = 1$, so there are no local observations and a response rule is a tuple of trades alone.  The exposed menus form the 2-participant context $(T_{\texttt{eager}}, T_{\texttt{hold}})$.  Matching buy/sell pairs in $T_{\texttt{eager}} \times T_{\texttt{hold}}$ that conserve value are parametrized by a quantity $q \in \{1,\ldots,5\}$ and a price $p \in [100, 102]$: Alice's trade is $((pq,0),(0,q))$ and Bob's is $((0,q),(pq,0))$.

\medskip
\noindent\textbf{Market-agent $M_1$ (passive matcher).}  Let $M_1 = \{\texttt{ready}\}$ with response rule
\[
\epsilon^{(1)}_{\texttt{ready}}(T_{\texttt{eager}}, T_{\texttt{hold}})
=\big(\,((300,0),(0,3)),\;((0,3),(300,0))\,\big)
\]
(quantity $q=3$ at price $p=100$) and update $u^{(1)}_{\texttt{ready}}(T_{\texttt{eager}}, T_{\texttt{hold}}) = \texttt{ready}$.  This market-agent produces exactly the event $e_1$ of Example~\ref{ex:event}.

\medskip
\noindent\textbf{Market-agent $M_2$ (aggressive midpoint).}  Let $M_2 = \{\texttt{ready}\}$ with
\[
\epsilon^{(2)}_{\texttt{ready}}(T_{\texttt{eager}}, T_{\texttt{hold}})
=\big(\,((505,0),(0,5)),\;((0,5),(505,0))\,\big)
\]
(quantity $q=5$ at price $p=101$) and $u^{(2)}_{\texttt{ready}}(\cdot) = \texttt{ready}$.  This produces a different event $e_2$:

\begin{center}
\begin{tikzpicture}[oriented WD, bby=2.5ex, bbx=1.5cm, bb port sep=1, bb min width=1.2cm]
  \node[bb={2}{2}] (E) {$e_2$};
  \draw[blue!70!black] (E_in1) to +(-.4cm,0) node[left, font=\scriptsize, text=blue!70!black] {Alice: $(\texttt{eager},\;(1000,0))$};
  \draw[red!60!black] (E_in2) to +(-.4cm,0) node[left, font=\scriptsize, text=red!60!black] {Bob: $(\texttt{hold},\;(200,20))$};
  \draw[blue!70!black] (E_out1) to +(.4cm,0) node[right, font=\scriptsize, text=blue!70!black] {$(\texttt{cautious},\;(495,5))$};
  \draw[red!60!black] (E_out2) to +(.4cm,0) node[right, font=\scriptsize, text=red!60!black] {$(\texttt{hold},\;(705,15))$};
\end{tikzpicture}
\end{center}

\medskip
\noindent\textbf{Market-agent $M_1'$ (richer state, same one-step output).}  Let $M_1' = \{\texttt{ready},\,\texttt{aggressive}\}$ with initial state $\texttt{ready}$ and response rules
\begin{align*}
\epsilon^{(1')}_{\texttt{ready}}(T_{\texttt{eager}}, T_{\texttt{hold}})
&=\big(\,((300,0),(0,3)),\;((0,3),(300,0))\,\big),\\
\epsilon^{(1')}_{\texttt{aggressive}}(T_{\texttt{eager}}, T_{\texttt{hold}})
&=\big(\,((505,0),(0,5)),\;((0,5),(505,0))\,\big),
\end{align*}
and trivial updates $u^{(1')}_{\texttt{ready}}(\cdot) = u^{(1')}_{\texttt{aggressive}}(\cdot) = \texttt{ready}$.  From its initial state, $M_1'$ produces the same event $e_1$ as $M_1$; the second state would have produced $e_2$.  $M_1$ and $M_1'$ are different market-agents with different carriers, yet a single observation of $e_1$ does not distinguish them.

\medskip
In all three cases value is conserved (total $(1200, 20)$), the selected trades lie inside the exposed menus, and update consistency uses the same transition maps $f_{\texttt{eager}}$ and $f_{\texttt{hold}}$ from Alice's and Bob's behavior data (Example~\ref{ex:agent-without-portfolio}) --- Alice transitions to \texttt{cautious}, Bob remains in \texttt{hold}.  The market-agents differ only in their carriers and response rules, which is exactly the mechanism-side degree of freedom that distinguishes one market from another.
\end{example}

A single one-step observation rarely determines the market-agent --- $M_1$ and $M_1'$ above are different market-agents that produce the same event $e_1$.  The questions of \emph{multiplicity} (which market-agents could have produced a given event or history) and \emph{uniqueness} (when a long-enough history determines the market-agent) form an open thread we will not pursue here.

Equilibria are a natural candidate interpretation of fixed points of the joint dynamics of participants and market.  As agents update their states under repeated event production, and the market updates its own, an equilibrium is a configuration on which both updates idle.

Portfolios have been carried alongside the market-agent state throughout this discussion.  They constrain which trades an agent can actually realize, and events change them, but the behavioral data above deliberately separated willingness to trade from current holdings.  The next section packages this set-theoretic description in the formal notation used below and records the corresponding portfolio recombination target.

%% ===================================================================
\section*{The market-agent polynomial}
%% ===================================================================

The preceding section described the market-agent construction in ordinary language.  We now give the corresponding polynomial.  We use the standard position--direction notation for polynomial functors,
\[
p=\sum_{i:p(1)}\yon^{p[i]},
\]
where $p(1)$ is the set of positions and $p[i]$ is the set of directions at the position $i$.  We also use the standard Dirichlet tensor product $\otimes$, its internal hom $[p,q]$, and the dual $p^\vee\coloneqq[p,\yon]$; see Spivak's references on categorical structures in $\poly$ and on polynomial coalgebras as generalized dynamical systems.  The only readings needed below are these: tensor packages simultaneous interfaces, internal hom packages parameterized maps, and the dual packages a response rule to every position of a polynomial.

\subsubsection*{Agents without portfolio}

Define
\[
P_X \coloneqq \sum_{T\subseteq R\times R} \yon^{T X}.
\]
Here juxtaposition $TX$ in the exponent denotes the cartesian product $T\times X$; we use this convention for products of direction sets throughout.  A place of $P_X$ is a trade menu $T\subseteq R\times R$.  The directions at that menu are $T X$: an acceptable visible swap $(g,h)$ together with a local observation.  This matches the portfolio-free behavioral component of the agent data of \S1, with the local observation set $X$ playing its assigned role.

For any polynomial interface $p$, a coalgebra $A\yon^A \to p$ is the standard polynomial-functor presentation of a stateful system with state set $A$ and interface $p$.  In the present case $p=P_X$, this says that each state $b\in A$ chooses a trade menu and an update map into $A$.

\begin{definition}[Agent without portfolio]\label{def:agent-without-portfolio}
An \emph{agent without portfolio} is a coalgebra
\[
A\yon^A\to P_X.
\]
Equivalently, regarding $A$ as a constant polynomial, this can be curried as a map
\[
\yon^A\to [A,P_X].
\]
Concretely, this is the data
\[
\prod_{b\in A}\sum_{T\subseteq R\times R}A^{T X}.
\]
Thus each state $b\in A$ chooses a trade menu $T_b\subseteq R\times R$ and an update map
\[
T_b X\to A.
\]
The name \emph{without portfolio} records that no current holding $r \in R$ is part of the agent state: $A$ stores only the agent's internal state, and the menu $T_b$ lists candidate visible swaps without specifying which holding the agent currently has.  The directions in $T_b X$, written $(t,x)$, encode an executed trade $t=(g,h)$ together with the agent's local observation $x$.
\end{definition}

\subsubsection*{Market agents}

Two moves lift the construction from a single agent to a market-agent: the tensor product in $\poly$ packages the finite participant context exposed to the market, and the dual packages the market's response rule.  A market mediates many exposed menus at once, so we package arbitrary finite participant contexts in a single polynomial:
\[
P_X^{\mathrm{fin}}\coloneqq\sum_{n\in\nn}P_X^{\otimes n}.
\]
The superscript $\mathrm{fin}$ records that we sum over all finite arities, so a single object holds every $n$-participant context at once.  Written in position--direction form, this is
\[
P_X^{\mathrm{fin}}
\cong
\sum_{n\in\nn}
\sum_{T_1,\ldots,T_n\subseteq R\times R}
\yon^{T_1X\cdots T_nX}.
\]
A place is a finite list of menus, one for each participant, and a direction at that place chooses one trade-and-observation pair for each participant.\footnote{One could allow the $i$th participant to have its own local type $X_i$; we keep a single $X$ since heterogeneous local vocabularies can be folded into a larger common observation type when needed.}

Applying the dual $(-)^\vee$ to $P_X^{\mathrm{fin}}$ packages a response rule for every finite context: a way of selecting, from each $n$-tuple of exposed menus, an $n$-tuple of trade-and-observation pairs.  A market agent is then the stateful object participants implicitly posit when they ask what the market will do with the exposed menus.

\begin{definition}[Market agent]\label{def:market-agent}
A \emph{market agent} is a coalgebra
\[
M\yon^M\to (P_X^{\mathrm{fin}})^\vee.
\]
An element $m\in M$ is a market state.  Unwinding the dual, the state $m$ determines a response rule
\[
\epsilon_m\in
\prod_{\substack{n\in\nn\\ T_1,\ldots,T_n\subseteq R\times R}}
T_1X\cdots T_nX,
\]
i.e.\ for each finite list of trade menus $(T_1,\ldots,T_n)$, the market picks a particular trade $t_i\in T_i$ inside each menu together with the local observation $x_i$ associated to that trade; the resulting tuple is $\epsilon_m(T_1,\ldots,T_n)=((t_1,x_1),\ldots,(t_n,x_n))$.  The state $m$ also specifies an update map
\[
u_m\colon P_X^{\mathrm{fin}}(1)\to M,
\]
whose domain $P_X^{\mathrm{fin}}(1)\cong\sum_{n\in\nn}\{(T_1,\ldots,T_n):T_i\subseteq R\times R\}$ is the set of finite menu contexts.  When an actual context $(T_1,\ldots,T_n)$ is presented the market outputs the tuple $\epsilon_m(T_1,\ldots,T_n)$ and moves to the new market state $u_m(T_1,\ldots,T_n)$.
\end{definition}

\subsubsection*{Reintroducing portfolios}

The omission of portfolios from the market-agent polynomial was deliberate but temporary.  Up to this point, portfolios have been carried alongside agent state: they constrain which trade directions an agent may expose, but they have not themselves been made part of the polynomial-functor framework.  The reconstruction problem is to isolate the portfolio dynamics that, when recombined with portfolio-free agency, recovers the original agents-with-portfolios picture.

Define a portfolio category whose objects are elements $x\in R$.  A morphism, or direction, $x\to y$ is a triple $(k,t_1,t_2)\in R^3$ such that
\[
k+t_1=x,\qquad k+t_2=y.
\]
This direction means: leave the common part $k$ unchanged and replace $t_1$ by $t_2$.  The pair $(t_1,t_2)$ is the visible trade, while $k$ records the untouched part of the portfolio.  In polynomial-comonad language, the positions are portfolios and the directions out of a position are exactly these portfolio-changing moves; the category structure supplies identities and composition of such moves.

\begin{example}\label{ex:portfolio-morphisms}
We illustrate the portfolio category on the event $e_1$ of Example~\ref{ex:market-agent}.  Alice's portfolio transitions from $v_A = (1000, 0)$ to $v_A' = (700, 3)$.  A natural decomposition is
\[
k_A = (700, 0),\qquad t_{A,1} = (300, 0),\qquad t_{A,2} = (0, 3),
\]
so $k_A + t_{A,1} = v_A$ and $k_A + t_{A,2} = v_A'$: $700$ in cash is untouched, $\$300$ is given up, $3$ shares are received.  Bob's portfolio transitions from $v_B = (200, 20)$ to $v_B' = (500, 17)$, decomposed as
\[
k_B = (200, 17),\qquad t_{B,1} = (0, 3),\qquad t_{B,2} = (300, 0):
\]
$\$200$ in cash and $17$ shares are untouched, $3$ shares are given up, $\$300$ is received.  The swap structure is visible in the matching $t_{A,1} = t_{B,2}$ and $t_{A,2} = t_{B,1}$: what Alice gives up is what Bob receives, and vice versa.  Aggregating recovers value conservation at the level of these morphisms, $t_{A,1} + t_{B,1} = (300, 3) = t_{A,2} + t_{B,2}$.
\end{example}

We record the desired recombination as a conjectural target:
\begin{equation}\label{eq:portfolio-recombination-target}
\Cat{AgentWithPortfolio}
\simeq
\Cat{AgentWithoutPortfolio}\times\Cat{Portfolio}.
\end{equation}
The equivalence in \eqref{eq:portfolio-recombination-target} is not a theorem established here.  It states what the later development should prove once the portfolio category and the portfolio-free agents have been specified with enough structure.

\section*{Events, revisited}
\label{sec:events-revisited}
%% ===================================================================

The goal of this section is to restate the event conditions of \S2 using the market-agent vocabulary introduced above.  The original exchange-event definition records what happened to the participants; the market-agent version adds a witness for how the selected trades were produced.  Thus the \S2 definition is recovered by existentially forgetting that witness.

Fix a finite participant list $I=\{1,\ldots,n\}$.  For each $i\in I$, let $(A_i,T^i_{-},f^i_{-})$ be the portfolio-free behavioral data of a \S1 agent, with initial state $a_i\in A_i$, post-state $a_i'\in A_i$, initial portfolio $v_i\in R$, and post-portfolio $v_i'\in R$.  Also fix a local observation $x_i\in X$ for each participant, and let $M$ be a market agent in state $m\in M$.  Suppressing the participant superscripts on menus and update maps, an \emph{event-with-market-agent} is such data satisfying:

\begin{description}
  \item[\quad Value conservation.]
  \[
    \sum_{i\in I} v_i=\sum_{i\in I} v_i'.
  \]

  \item[\quad Trade consistency.]
  For each $i\in I$, the trade $t_i$ extracted from the market-agent response lies in $T_{a_i}$, and writing $t_i=(g_i,h_i)$ there is some $k_i\in R$ such that $v_i=k_i+g_i$ and $v_i'=k_i+h_i$.

  \item[\quad Update consistency.]
  The same trade and local observation update the participant by
  \[
    f_{a_i}(t_i,x_i)=a_i'.
  \]

  \item[\quad Market-agent consistency.]
  If $\epsilon_m$ is the response rule of the market state $m$, then at the participant context $(T_{a_1},\ldots,T_{a_n})$ it returns exactly
  \[
    \epsilon_m(T_{a_1},\ldots,T_{a_n})
    =
    ((t_1,x_1),\ldots,(t_n,x_n)).
  \]
\end{description}

The exchange event of \S2 is the existential reading of this definition: it is the same participant data, with the market-agent omitted, satisfying value conservation, trade consistency, and update consistency, such that there exists some market agent in some state witnessing the market-agent consistency condition.

Each generator of the event prop is a market-agent-witnessed event in this sense; the deeper rederivation of the generators and their relations is deferred to the next pass.
